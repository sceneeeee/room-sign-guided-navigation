# M4 手持实机预检

当前具备开展静态预检的工程条件。已验证的浏览器链路使用虚拟摄像头和合成检测。正式手机或 Camo 的采集缓冲、端到端时延和有人按建议移动的回合仍待现场验收。每条输出仅供观察，`motion_authorized=false`。

## 开始前记录

- 现场设置包括操作者、独立读号员、设备和浏览器版本、相机输入、分辨率、光线、网络拓扑、策略和目标。优先用回环地址、桌面浏览器和 Camo 作为摄像头输入。首次预检固定 Rule，保持现场操作和运行时一致。
- 记录运行分支、HEAD、是否有未提交修改、Python 和推理组件版本、权重及其 SHA-256、实际设备和检测类别。OCR 使用本地已准备好的模型文件，记录模型名或缓存版本。预检产物保存到本地 `outputs/`。
- 软件结项环境已核对 Python 3.13.13、Gradio 6.30.0、PyTorch 2.14.1、Ultralytics 8.4.184、RapidOCR 3.10.0、ONNX Runtime 1.31.0。现有 `yoloe-11s-seg.pt` 的 SHA-256 为 `8e439445c87338b79d9ce21dec109f4621e26df67e94d26ea1a98c1e64dce3e3`，与保存的 Isaac manifest 一致。现场使用的文件应重新核验。

```bash
sha256sum yoloe-11s-seg.pt
.venv/bin/python -m pip show gradio torch ultralytics rapidocr onnxruntime
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 \
  .venv/bin/python apps/multidoor_search.py --weights yoloe-11s-seg.pt --device cpu
```

启动后用 **New session / reset**、**Click to Access Webcam** 和 **Record** 开启流。完整操作路径见 [M4 handoff](m4-handoff.md)。

## 静态和原地检查

| 项目 | 操作与通过条件 |
|---|---|
| 单门静态 | 将摄像头固定，观察无遮挡的门及门牌。确认框、临时 track、OCR 原文和动作提示来自当前画面。连续看两帧再尝试人工关联。复测边缘门框、反光和无读数。 |
| 多门静态 | 至少两门同屏，含一块相邻墙牌。手选正确目标，核对相邻门或歧义牌不会获得错误绑定。尝试在持续同屏的另一扇门复用已用实体 ID，应拒绝绑定。遮挡门牌或移开视线时，旧绑定失效。 |
| 转向和人工反馈 | 在固定站位、清空附近障碍后，原地小幅调整相机朝向。核对左右方向和动作 ID。只有确实完成且安全才反馈。重复、错误或过期 ID 不能完成动作。检查反馈后须有新 RGB 才能收到下一条提示。 |
| 慢推理 | 在静态设备预检时观察推理较慢但仍处于新鲜度窗口的回合。状态轮询应显示当前动作，同一待反馈动作保持类型和 ID。独立测量显示时延。既有期限无法满足时，核对动作撤下和拒绝反馈。 |
| 停读与确认 | 当前有效实体绑定至少有两帧独立、相同解析结果后才能进入 `VERIFY_TARGET`。轻微偏心时继续停读，无待反馈移动。独立读号员直接看实体标牌，再输入读数。一次 OCR、错门、冲突读数或空确认都不能产生 `FOUND`。 |
| STOP 与超时 | 在待反馈时点 **Emergency STOP**，再看一条晚到更新。页面应保持停止且撤下建议。单独试验让有效 RGB 持续到动作签发后 6 秒，以及不点击清空就中断有效 RGB 约 2 秒。两个截止条件均可独立撤销待反馈动作，日志应区分 `action_expired` 和 `rgb_stream_interrupted`，禁止生成自动完成事件。 |
| 清空、断线与重连 | 分别清空摄像头、断开源或关闭页面。在断线或 STOP 前的帧、反馈及显示更新不能影响新会话。页面断开后须重载再开新会话，用新 RGB 发出新动作。 |
| 采集缓冲 | 用同一外部记录对照物理遮挡或明显视觉变化与浏览器画面及提示。检查停止源、恢复和反馈前后的过渡。记录最慢表现与重复旧帧。服务端单调收帧时刻和浏览器绘制时刻分属不同钟域，浏览器收帧日志不能证明手机采集时刻。 |

若相机冻结后仍上传相同像素，重复帧守卫可能先于 watchdog 停止会话。保留实际停止原因。保持 TTL、watchdog 和 STOP 检查开启。

## 失败取证

每项保存用例、会话 ID、预期与实际、相关动作 ID、关联状态、停止原因和是否观察到旧帧。用 **Prepare log download** 保存完整 JSONL，包含失败和中止回合。回放应还原终态和拒绝的反馈。用于定位缓冲的原始拍摄和可能含有个人信息的素材只存放在批准的本地位置。

```bash
.venv/bin/python -m roomnav.search_cli replay outputs/m4-preflight/episode.jsonl
```

## 开始真人按建议移动前

- 正式手机或 Camo 在预计使用的环境中逐项通过上述预检。实际缓冲和延迟有记录，现场可辨识并处理过期画面。
- 操作者能独立判断通道安全和选择拒绝，独立读号员知道如何从标牌现场确认。走廊和动线已确认合适，现场可随时终止。
- STOP、断流、旧反馈、重置隔离和导出回放均在该设备组合验证通过。任何旧动作重现、错误实体绑定或确认后错误的 `FOUND` 都应先复现并排除。

达到这些条件后再安排有人监督的短回合。当前记录支持静态预检，手机实测和真人移动验收仍待执行。
