# 项目路线与两人分工（Video-first）

## 目标与边界

- **实验平台：** 人携带 USB RGB 摄像头，MacBook 浏览器取帧；通过 SSH 访问远程 GPU 电脑进行视觉与推理。
- **任务：** 在真实教学楼读取字母数字门牌（如 `EB104`），在目标位置未知时利用已见门牌、指示牌和有限拓扑信息选择下一观察目标。
- **开发顺序：** 实时采样链路 → 真实门牌 OCR → Landmark Memory + 规则/VLM 推理 → 线下搜索闭环 → 对照评估。
- **不做：** 当前阶段不接 Frogbot、深度相机、SLAM、Nav2 或云台；不声称完整复现 ReasonNav。
- **照片及录制视频：** 作为标注集、失败复现与回归数据，不单列初始开发阶段。

## 里程碑

| 阶段 | 工作内容 | 验收标准 | 负责人 |
| --- | --- | --- | --- |
| **M0 视频接入** | MacBook 摄像头 → Gradio 定时采样 → SSH → GPU RapidOCR → 返回原始文本 | 持续接收采样帧、远程显示 OCR，记录延迟和实际采样间隔 | 成员 B |
| **M1 视觉感知** | 门/门牌检测、完整编号识别、模糊帧过滤、跨帧确认及去重 | 真实走廊的可信门牌记录，保留错误样本 | 成员 B |
| **M2 地标记忆与推理** | 观测转 JSON、Landmark Memory、局部编号规则及 VLM 搜索建议 | 同一已知信息下输出可复核的搜索建议 | 成员 A 主导，两人集成 |
| **M3 现场闭环** | 人按系统建议行走，现场使用 Codex 辅助代码调试和复测 | 完成未知房间搜索，保留日志与版本 | 成员 B 主导现场；成员 A 调整推理 |
| **M4 实验对照** | 逐门搜索 / 规则 / VLM 在相同起点、信息预算下对比 | 成功率、门数、距离、用时、失败分析 | 两人 |
| **Future** | 视结果评估 Frogbot / 机器人导航集成 | 另定计划 | 暂不承诺 |

当前代码：`apps/live_demo.py` 提供远程视频帧 OCR 原型，实际 USB 摄像头 / SSH 尚未验收。**M2.1 Landmark Memory 和 M2.2 证据分级规则基线已在独立 CLI 实现**；门牌检测、视频地标关联、VLM、实时写入地标与线下闭环仍待开发。详见 [M2.2 设计](m2-rule-reasoning.zh-CN.md)。

## 分工及现场调试

- **成员 A（你）：** Landmark Memory、局部编号规则、VLM 高层策略、搜索评估；M0/M1 可用模拟观测并行开发。
- **成员 B（队友）：** 视频接入、OCR、门/门牌检测、去重、**实际教学楼测试**；线下通过 MacBook + SSH + GPU 调试，使用 **Codex** 辅助查看错误日志、修改代码、调参、复测并记录提交。
- **共同：** 对齐 `docs/interfaces.zh-CN.md` 中的观测接口，连接感知与决策模块，记录真实失败案例。

**注意：** Codex 是现场开发工具，不是门牌识别模型或导航推理系统。每次现场代码修改由人审核，并记录版本及复测结果。

## 研究与复现边界

主要参考 [ReasonNav (CoRL 2025)](https://reasonnav.github.io/) 和 [官方代码](https://github.com/ReasonNav/ReasonNav)。本项目首先验证视觉文字观测与高层搜索策略，尚非完整机器人复现。OCR 错误、跳号和冲突编号条件下的主动搜索属于需进一步文献核验的候选研究问题。
 

**M2.3 开发规格：** [可替换 LLM Planner 的接口、约束与验收标准](m2-llm-planner.zh-CN.md)。此阶段仍为计划，未实现或完成真实模型测试。
